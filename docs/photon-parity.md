# 与 Java 版 Photon 1.4 的差异记录

对照对象：Java 1.20.1 + Iris 1.7.6 + Photon 1.4（玩家实际使用的设置：`EDGE_HIGHLIGHT`、`SKY_GROUND`、`SNELLS_WINDOW`、
`BLOCK_ENTITY_SHADOWS`、`GALAXY`、`WATER_CAUSTICS` 开，`DOF_INTENSITY=0.20`，`AURORA_SNOW=AURORA_ALWAYS`）。
Photon 1.4 的设置项与本移植所依据的 Photon 版本完全相同。

记录日期：2026-11-19。等级：一级为随处可见，二级为特定场景明显，三级为细节或少见。

## 二、两边都有，做法不同、结果不同

| 等级 | 功能 | Photon | 移植版 | 结果差别 |
|---|---|---|---|---|
| 一级 | 天气变化（已补齐，近似） | 由世界天数和时间决定 | `world_age()` 用月相（天数 % 8）和一天内的时间推算，开关 `WORLD_AGE_ON_GAME_TIME`（`common.wgsl`）；无开销 | 同一世界时间云量、云型与 Java 一致，重启不变；天数每 8 天回绕而 Java 是 128 天，完全一致需要引擎给世界天数；时间冻结时云也冻结（和 Java 相同） |
| 一级 | 天空光（`SH_SKYLIGHT`）（已补齐） | 含云的整片天空投影成球谐系数 | 低分辨率天空图（192×96，分成四块放在 `cloud_shadow_tex` 四个角，阴影查表够不到）含云、极光、雾；球谐从上一帧的天空图投影；开关 `sky_map_clouds`，每帧只更新 1/4 | 与 Photon 同做法；阴天、多云天更接近；开销：森林约 0.03 ms，水面视角约 0.3 ms（含反射） |
| 一级 | 抗锯齿（TAA 已彻底移除） | TAA（带画面抖动） | SMAA 或 FXAA + 锐化；引擎没有投影抖动，TAA 无法工作，已删除 `taa` 选项、`taa_hist` 历史输出和 TAA 分支；光影里的逐帧抖动也固定不动 | 贴图更锐利，远处会闪；腾出 1.0 个屏幕缓冲预算和 1 个选项位 |
| 一级 | 水面上的云倒影（已补齐） | 反射整张含云天空图 | 反射直接采样上面的天空图（开关同 `sky_map_clouds`，一次硬件双线性读取） | 屏幕外的云倒影也有，不再闪烁；天空图是 192×96，比 Photon 的 191×108 略低 |
| 一级 | 云的清晰度（已改善） | 历史缓冲全分辨率 | 历史仍是半分辨率（全分辨率要多 3.0 的缓冲，TAA 移除后仍超出预算），合成时从双线性改为 Catmull-Rom 放大（只在有云的像素，邻近空洞时退回双线性）；开关 `clouds_bicubic_upsample` | 原因：半分辨率历史加双线性放大，云边缘被抹开约一个纹素；放大改动后云边缘明显更锐，略多一点颗粒；开销：满天云的视角约 +0.45 ms（3840×2160） |
| 一级 | 光束（丁达尔效应）（已补齐，之前误记为一致） | 沿视线逐步计算雾，按雾浓度加权，每步查阴影，天空像素也算 | 12 步（天空 6 步）取阴影，每步权重用雾的空气质量乘视线上的透射；阴影图以外的部分按无遮挡；天空像素算到渲染距离，合成时天空也乘光束；开关 `vl_weighted_shafts`。第二次修正（照 `raymarched.glsl`）：光束开启时雾的太阳光项不再乘天空光（只由阴影图遮挡），环境光项仍乘天空光但天空像素不乘；雾密度改用 Photon 光束雾自己的密度 `air_fog_vl_airmass`（`common.wgsl`，分段闭式积分）：海平面以下（y<39）为 0，39 到 63 线性渐入，63 到衰减起点（瑞利 93、米氏 70）为 1，之后按半衰期指数衰减，320 以上为 0；合成里的雾、天空图里的雾和光束权重都用它 | 光束权重与画出来的雾一致，树荫下、屋檐下的光束不再被天空光压暗；地下（y<39）没有雾；解析雾是旧的未钳制版本，海平面处约浓一倍，只在光束关闭时使用；开销：森林约 +0.04 ms，满天云视角约 +0.24 ms |
| 二级 | 玻璃后的天空和远景（已补齐） | 合成时按不透明层的深度，从前往后叠加云和雾 | 合成后处理只看得到玻璃的深度，读不到玻璃背后的深度（`opaque_depth` 只在材质阶段有）；所以染色玻璃、有色玻璃、冰在材质阶段读入背后画面，背后是天空时用天空图（含云和雾）、是地形时叠加玻璃到背景之间的解析雾，差值按玻璃的透明度混入；开关 `behind_glass_sky` | 透过染色玻璃、冰看天空有云，窗外远景有雾；限制：玻璃背后的另一层半透明（水、玻璃）读不到，不透明玻璃之外的云不叠加 |
| 二级 | 环境光遮蔽（已补齐，无弯曲法线） | GTAO，只压暗天空光，提供弯曲法线 | 半分辨率 GTAO（2 切片 × 3 步，半径 2，多次反弹近似），沿用时间历史；材质阶段把天空光占比打包进 `set_surface`，合成时 `color *= mix(1, ao, 占比)`；开关 `gtao`（关闭回到旧 SSAO）；比旧 SSAO 约多 0.1 ms | 阳光、方块光和自发光不再被压暗；没有弯曲法线，天空光仍按表面法线取球谐 |
| 二级 | 太阳轨道倾角（受引擎限制，未处理） | `sunPathRotation` 默认 -35°：太阳轨道向南倾斜 35°，正午约 55° 高度而不是头顶，日出日落的位置略低、更偏南 | 引擎按没有倾斜的 `light_direction` 渲染阴影图；光影 API 没有这个参数，`[shadow]` 只有分辨率、距离和选项。光影自己倾斜太阳会和阴影对不上，需要引擎提供倾角配置项 | 正午的影子在 Horizon 里短、在 Java 里长；日出日落的太阳位置有些不同。同在 0 刻，Java 的太阳低约 2°、偏南约 7°，常常整个藏在树或草后面，光柱更分明；为此加了选项“晨昏光柱”（`vl_twilight`，默认 2.0，1.0 与 Photon 相同）：太阳高度约 3° 到 15° 时（27° 前淡出），雾里被遮挡那部分的阳光按倍数加深（`1 - (1 - 光束) × k`），受光部分亮 `0.25 × (k - 1)`，无遮挡处的雾基本不变；用掉最后一个选项位（64 / 64） |
| 二级 | 反射和接触阴影 | 屏幕空间反射，无接触阴影 | 硬件光追反射和光追接触阴影 | 更准，但和 Java 不一样 |
| 二级 | 方块光颜色（已补齐） | 默认关闭彩色光，统一暖色 | 新选项“彩色光”（`colored_lights`，默认开）：关闭时方块光只用暖色，动态光源和粒子光源保留亮度但取暖色；为腾出选项位，去掉了泛光开关，泛光强度为 0 即关闭 | 关闭后与 Java 默认一致；无开销 |
| 二级 | 水下焦散（已补齐） | 阴影图里按水面法线折射计算 | 材质阶段由半透明阴影图找到阳光穿过的水面，用同一个波浪高度函数在阴影纹素间距的三个点上算 5 米折射的面积比，套 Photon 公式（0.25·exp(−5a)·面积比），去掉了固定系数 0.3；开关 `photon_caustics`；48 到 80 格外淡出为平均值 | 形状和亮度与 Photon 一致；开销：整屏都是浅水海底时约 0.9 ms，一般视角约 0.05 ms |
| 二级 | 植物环境透光（已补齐，用上一帧） | 由 GTAO 计算 | GTAO 输出每切片的 `max0(h.y − π/2)/π`，存在 `vlao_tex` 的 alpha 小数部分；材质阶段用 `previous_view_projection` 重投影读取上一帧的值，失效时退回 0.25 × AO；开关 `gtao_foliage_sss`（读取约 0.2 ms，树叶多的视角） | 与 Photon 一致，晚一帧 |
| 三级 | 手持光源 | 光影自己计算 | 引擎"动态光源"提供 | 需在游戏里开启动态光源（图形设置 → 质量 → 光照与实体）；照得比 Photon 远、略亮（第五节） |
| 三级 | 调色 | 白平衡 + 橙、青、绿单独饱和度 | 合并为一个"自然饱和度" | 默认值下差别很小 |

## 已经一致

大气和雾（系数）、阴影（柔和半影、彩色阴影、阴影滤波）、月相、银河、水体着色（水下阳光衰减、水底按红通道
压暗）、雨天水坑、景深、动态模糊、色调映射、暗角、边缘高光。游戏设置：渲染距离 18、生物群系过渡 2。

“光束和云隙光”之前记在这里是错的：云隙光（曙暮光）一致，但光束不一致，已移到上面的表并修复。

2026-11-19 的算法级审计（逐段对比两边代码）发现，之前按功能名单记为"一致"的项里还有差异，处理结果见下一节。

## 对比时要注意

- 两边执行 `/time set` 和 `/weather clear` 后在同一坐标、同一朝向截图；云因天气推算方式不同，对不上是正常的。
- 太阳直射处的亮度和暖色两次对比结论相反，需要在对齐时间后再判断。
- 光照相关的验证开关（`sh_skylight`、`sky_map_clouds`、`gtao`、`gtao_foliage_sss`、`photon_caustics`、`foliage_ambient_sss`、`water_sun_absorption`、`edge_highlight`）是
  `pack/options.wgsl` 里的常量，因为选项数已达上限 64。

## 三、2026-11-19 审计发现与处理

开销为 GPU 平均耗时（3840×2160，离屏），改动前后各测多轮，噪声约 0.1 到 0.3 ms。

| 状态 | 项 | 做法或跳过原因 |
|---|---|---|
| 已修 | 原版 AO | 原版 AO 只提亮后压暗反照率（`lift(ao,0.5)*0.9+0.1`，树叶无）；光照里的 `ao` 是 GTAO 的：后处理里天空光乘 `ao`、阳光漫反射乘 `ao²`（`AO_IN_SUNLIGHT`），不重复压暗 |
| 已修 | 云影强度 | `*0.8+0.2`（材质、实体、光束三处），云影内半影放大 `5-4*云影`；卷云影、双三次采样未做（云影图里没有卷云项，收益小） |
| 已修 | 积云细节 | 两层 worley 比例 0.0009、0.005，公式改为 `w0²`、`w1²·淡出`，淡出常数 +0.6；加上层云遮光项 `l0_shadow` |
| 已修 | 高积云 | 高度 3200、自己的密度 0.10（之前误用积云密度，消光大 10 倍；云影里同样）、细节 0.3、风 25 m/s 60° |
| 已修 | 云的远景透视 | 射线终点放大 2 倍 |
| 已修 | 高光 | 上限 4.0；太阳盘面积的 `NoH²`（`get_noh_squared`） |
| 已修 | 雨天大气去饱和 | 去掉 `(1-雨)` 因子（Photon 默认关闭） |
| 已修 | 染色玻璃、有色玻璃、蜂蜜、史莱姆 | 材质编号 81：f0 0.04、粗糙度 0.1、反射、SSS 0.5；冰 SSS 0.75；编号 14（竹、蘑菇块、杜鹃等）SSS 0.6，编号 15（羊毛、蛛网、仙人掌等）SSS 0.1 |

## 四、性能记录（2026-11-19，RTX 5070，测试环境与玩家设置对齐：shadowCache、framePacing precise、vulkan）

### 测量方法与限制
- 每个视角用 `gpu-passes` 的各通道耗时加整帧 GPU 平均；整帧对比用 A/B 交替各 3 轮取中位数。
- 这台机器的 GPU 同时被桌面程序占用，整帧数字会在两档之间跳动（同一份光影森林视角在 13.5 到 18 ms 之间），亚毫秒级的地形材质改动在这样的噪声里量不出来。只有各通道自己的计时稳定（天空通道 0.63 或 0.41 ms 几乎不抖），所以只保留了能用通道计时证明的改动。
- 地形不透明通道引擎不单独计时：整帧减去所有已计时通道，森林约 7 ms，是最大的一块。

### 分解（4K，用选项开关逐项关闭，数字有噪声，只作量级）
| 关闭项 | 整帧变化 |
|---|---|
| 整个阴影（含阴影图通道、材质阶段阴影、光束、SSRT 读阴影） | 森林约 -2.7，海面约 -4.8 ms |
| 阴影滤波四项同时降级（PCF 4 步、不搜遮挡、无彩色阴影、无焦散） | 森林约 -2.4，海面约 -3.4 ms |
| 遮挡搜索（`shadow_vps`） | 约 -1.2 ms |
| RT 接触阴影、SSRT 阴影、彩色阴影、焦散、SSAO、体积光 | 在噪声内（SSRT 在合成通道里只有 0.03 ms） |
| RT 反射关闭 | 海面反而 +0.9 ms（回到屏幕空间反射） |
| 镜面高光开关 | 一次 -2 ms，复测 -0.4 ms，判为噪声 |
| 边界雾（合成通道） | 合成通道 1.66 到 1.47 ms |
| 地形过绘 | 水面视角的半透明地形 0.65 个片元每像素；不透明地形没有可用计数 |

### 试过但没有保留
- 阴影滤波里把彩色阴影和水的 4 个取样推迟到有光透过时：整帧测量偏慢（森林 +1 到 1.5 ms，噪声内但方向一致），已撤销。
- RT 接触阴影在阴影图已为 0 时跳过：森林偏慢，已撤销（该光线本身几乎不花时间：关闭它整帧不变）。
- 边缘高光在步长落在自身像素时跳过取样：合成通道 1.66 → 1.66 ms，没有收益，已撤销。
- EASU & CAS（0.31 ms）：在 100% 分辨率下它的方向滤波仍会改变画面（0.22 的边缘混合），跳过不是像素一致，没有改。

### 引擎设置发现（测试环境，离屏）
- `upscaling`（质量到极致性能）：在这个光影下对全分辨率通道没有任何影响（天空 0.41、合成 1.65 ms 与原生相同，森林整帧不变），画面与原生相同；水面视角整帧变快是噪声之外的 -4.5 ms，原因未查明。光影自己的通道仍按全分辨率运行，所以不建议靠它提速。
- `taa:true`：对帧时间无影响，画面与关闭相同；光影没有投影抖动输入，建议保持关闭。
- 帧生成（`frameGeneration`）、`presentMode`、`framePacing`：离屏测试里呈现模式固定为 Immediate，没有交换链，测不出 12.8 ms 帧对 10.5 ms GPU 的差距，未测。`graphicsApi` 保持 vulkan（光线追踪走 Vulkan），dx12 未测。
- 光影自带的 EASU & CAS 只在 `cas_intensity` 大于 0 时运行，对 resolutionScale 100 也一样，和引擎的放大互不干扰（引擎放大没有生效）。
- 原因在引擎里：载入光影包时引擎关闭 TAA，放大是 TAA 的一部分，所以也不生效（`world_post.rs`：光影按窗口 × 渲染比例绘制）；帧生成在光影包有自己的后处理通道时不运行（`gfx.rs` 的帧生成条件）。对这个光影包，能提速的只有渲染比例（`resolutionScale`）。
